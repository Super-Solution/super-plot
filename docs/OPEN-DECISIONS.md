# Decisions

## Settled

- **Name: Super Plot** (owner, 2026-11-19). Used everywhere (`@supersolutions/super-plot-*`, `--sp-*`, `<super-plot>`).
- **Palette.** The default stays the TradingView set. A colour-vision-safe preset is added next to it (`accessible`, `accessible-dark`), so nobody has to choose.
- **Shared theme package: not now.** "Alias" means each library keeps its own tokens (`--sp-*`, `--sc-*`) and Super Plot reads Super Chart's as a fallback (`createTheme('light', { alias: { text: ['--sc-text'] } })`), so a page that themes Super Chart already themes Super Plot. A shared `super-theme` package would replace the aliases with one source of tokens; build it when a third library needs the same tokens.
- **Canvas renderer, radar, treemap, sankey, browser tests, Go and Python ports**: built (see DESIGN and `ports/`).
- **WebGL and 3D maps** (owner, 2026-11-19: "一步到位 ... 做到 P3"): built inside the existing packages (no new package names), existing specs and APIs unchanged. **No default boundaries ship**: users import their own; presets are templates only; disputed areas are drawn like any other region unless the spec says `dashed` or `muted` (see MAPS.md).
- **Competitor features (owner, 2026-11-19: "也把你整理出來的特點也加入進來")**: built in round 4, see DESIGN "Borrowed from competitors": transform, zoom/pan/brush with JSON selections, hover/render events and plugins, per-chart imports, patterns, data table, canvas keyboard steps, shadcn theme, small multiples, live append, hexagon density, lines over bars, the fast dot path. Still local only.
- **The round-5 refusals** (owner, 2026-11-19: "除了這個之外 其他都做"): gauge, word cloud, non-map 3D, dual y-axis, broken axis and animated data transitions are built in round 6, each safe by default and switchable off, with the risk stated (DESIGN "Round 6"). The expression language stays out: data are computed before they reach the spec.
- **Tree-shakable chart registration**: built (`/base` + `/charts`); the package roots still register everything.
- **Package split** (owner, 2026-11-20, asking for it: "有些人可能只需要用到基本圖表、3D 或者是特定圖表 ... 更模組化一點"; the proposal was approved): three npm packages stay (`core`, `web`, `react`), modular inside, and the all-in-one roots stay for quick starts and agents. Inside core: seven chart groups (`/charts/basic`, `/business`, `/stats`, `/maps`, `/hierarchy`, `/3d`, `/text`; each chart in exactly one), transform steps registered like charts (`/transforms`; an unregistered step is the error `transform_not_registered`), the canvas renderer (`/canvas`) and the map/3D projections (`/view`) out of `/base`. In web: the canvas renderer is a chunk loaded on demand. Sizes and budgets: INTEGRATION "Entry points and what they cost", `npm run size`. Notes: `docs/design-notes-0.4.0/split.md`.
- **`sonifyNotes` and sound stay in web `/base`** (settled with the split): moving the export out is easy, but `sonify()` returns its controller with the `notes` at once and reports `sonify_empty` before it returns, which needs the note plan (the bulk of `sound.ts`) in the bundle. Loading it on demand would change that contract for 1.6 KB gzip; not done.
- **One new runtime dependency** in `super-plot-web`: `earcut` (ISC, about 3 KB, polygon triangulation for WebGL maps), loaded only with the WebGL chunk.

## Recommended, waiting for the owner

- **Super Chat card.** The generic card is `super.plot`, `{ kind, id?, title?, height?, spec, alt }`, in super-protocol 0.3.0 (published 2026-11-20). Super Plot's chat plugin (`packages/integrations/chat-plugin`) imports it from the protocol; `fromChatChartCard` still converts the older built-in `chart` card. Merging and publishing 0.3.0 is the protocol's decision.

- **Licence: Apache-2.0** (owner, 2026-11-19: "那就用 Apache 2.0 吧 ... 署名 公司那些全部都用跟其他庫一樣"): `LICENSE` and `NOTICE` at the root and in each package, `license: Apache-2.0` and `author: SUPER SOLUTION LABS INC` in every manifest, an SPDX header in every source file, the same as super-chat and super-protocol. Apache-2.0 has no "or-later" form, so the identifier is plain `Apache-2.0`.

## Open

1. **Publishing.** Nothing is published to npm or PyPI yet; packages stay `private`. The Go module path follows the repository (`github.com/super-solution/super-plot/ports/go`); the Python distribution name `super-plot` is a placeholder.
2. **A native renderer in Go or Python?** The ports validate, describe and compute; they do not draw. Drawing in a second language means porting the layout of all 28 chart types (about 3,500 lines of TypeScript, plus text measurement, which differs per language) and keeping pixels close, not identical. Worth it only if a backend must produce SVG or PNG without Node. The scene is already a flat JSON structure, so the cheaper alternative is to run the TypeScript renderer where Node is available.
3. **Rust.** The Rust core is closed per strategy; a Rust port would be a separate decision and would check against the same conformance data.
4. **Chat plugin package**: built (`@supersolutions/super-plot-chat-plugin`, private, 0.1.0, Apache-2.0), against protocol 0.2.0 from npm. Not published (item 1).
5. **More chart types.** Round 5 added 12 (waterfall, funnel, bullet, bump, violin, calendar, sunburst, parallel, waffle, beeswarm, timeline, stream graph via `stack: 'center'`). Still open: network graph, chord, arc, venn, marimekko (layout must be made deterministic; hard to read). Round 6 added gauge, word cloud, scatter3d and surface at the owner's request (safe by default). Still refused with reasons in COMPETITIVE.md: pictorial bars, 3D bars.
6. **Vue, Svelte, Angular bindings.** Settled for now: the element is documented and tested for all three (properties, events); native packages only if DX asks.
7. **Declared linking between charts.** The page-level part is built: `sync` (hover, zoom, brush across plots sharing a key). Still open: a selection named in one spec and used as a `transform` filter in another, without host code.
8. **Raise the 50,000-row cap?** WebGL can draw several hundred thousand dots, but the cap is part of the validation contract (ports, conformance). Keep or raise per chart type.
9. **Basemap tiles or labels** (place names, roads) are out of scope for a statistical map; add only on demand, and never from a proprietary provider by default.
10. **Docs home.** The Super Kit principles now live in `super-dev-docs` (PR #7, from another thread); a Super Plot page in its `10-architecture` follows once the library is pushed.
11. **Row cap for the data table** (1,000) and the hexagon threshold (10,000 points): proposals, easy to change.
12. **Drawing in a worker** (`OffscreenCanvas`, Chart.js): a host can already pass any 2D context to `drawScene`; building it into the binding needs the scene on both threads for hover and keyboard. Worth it only if a page measures main-thread jank on big charts.
13. **Arrow / columnar input** (deck.gl): would add a dependency or a second data shape; rows stay the contract unless a use case needs millions of rows.
14. **Hydration in React.** `renderToSvg(spec, { hydrate: true })` is adopted by the web binding; React's `<SuperPlot>` still renders an empty div on the server. Server components would need the React binding to render the SVG string itself.
15. **Round-5 choices to confirm** (each has its reason in `docs/design-notes-0.4.0/`): funnel drawn as centred bars (no trapezoid); waffle uses `label` like pie; `fold` drops the folded columns (Vega-Lite keeps them); window `rank` is competition rank (1, 2, 2, 4); loess without robustness passes; box `outliers` kept next to the new `points` (deprecate later?); the colour check warns only for user `colors` (the theme's "Other" grey is close to cyan in the default palette, 5.8); the toolbar's sound button only when listed; `announce` speaks only while the chart has focus or shows a table.
16. **Round-6 choices to confirm** (reasons in `docs/design-notes-0.4.0/r6-*.md`): gauge notices (`max_derived`, `value_outside_range`) are warnings, not `info`; at most 6 gauges and 150 words; 3D default camera pitch 60, bearing 35, and `perspective_3d` shown even when orthographic; a repeated surface point keeps its first value; on lines the break is a gap over the line, not two lines; dual-axis lines are not zero-aligned (bars are); a fixed `domain` on bars with `yRight` is widened to include zero; transitions skip above 5,000 marks (an estimate) and drill-down keeps the entrance animation; `onCameraChange` is typed `Camera | Camera3d` (a handler reading `c.lng` needs a guard).
17. **The `super.plot` card is an import; the reference shell stays a copy.** super-protocol 0.3.0 was published on 2026-11-20. The chat plugin now imports `PLOT_CARD_KIND`, `plotCardKind`, `validatePlotCardSpec`, `PLOT_LIMITS` and `PLOT_FALLBACK_MESSAGE` from it, and `src/card.ts` is deleted. The reference shell stays a marked copy in core (`packages/core/src/ref.ts`), because core imports nothing, and in the Go and Python ports; all three are held to the protocol's own cases (`conformance/card-ref.v1.json`, vendored). `tests/plugin/plot-card.cases.json` still checks the imported validator against the protocol's cases.
18. **Chart linkage is owned by the Super Chart side.** References into Super Chart cards (the protocol's `parseChartRef` vocabulary: `key`, `from`/`to`, `low`/`high`) and any linking between a Super Chart card and a Super Plot card (a hover in one lighting the other) belong to Super Chart and the host. Super Plot only answers references to its own cards; nothing here reads a chart card.
19. **Reference choices to confirm** (built this way, each easy to change; notes in `docs/design-notes-0.4.0/refs.md`):
    - the vocabulary is four names, `key`, `x`, `y`, `series`, read per chart from `RefShape`; dates are whole ISO periods in UTC (`2026-03` is all of March) and ranges are inclusive at both ends, unlike the brush's half-open `filters`;
    - pie, donut, waffle, box and violin answer `series` with their legend column, so a slice or a box can be named either way;
    - `format` writes names in alphabetical order, as the protocol does; a label names the lane on row charts ("day Mon, hour 9");
    - `ref_spec_invalid` has one fixed reason (`validatePlot` lists the issues), so the three languages agree byte for byte;
    - `annotations[].by` is an enum (`author`, `assistant`), `note` is capped at 2,048 characters, and `maxAnnotations` went from 50 to 256 for agent annotations;
    - a `reveal` resets the zoom (or a map's camera) rather than panning to the match; what a click revealed stays highlighted after the host's `leave` until the viewer moves onto the plot or presses Escape; the agent's `plot_highlight` is a draft that goes the same way;
    - the plugin rejects an agent annotation the plot would cut (`string_truncated`, a note over 2,048 characters) instead of drawing it shortened, and forces `by: "assistant"` on everything the agent adds;
    - the plugin plays a card's entrance animation once; later spec or annotation changes redraw in place;
    - at most 2,000 marks are outlined, thin and without a halo above 200.
20. **Size of references in web `/base`: +6.3 KB gzip** (40.3 to 48.1 with the earlier row bookkeeping; core `/base` +1.5 KB). The protocol's `ref()` answer is synchronous, so `highlight` and `reveal` must resolve at once, and the resolver (`resolve.ts`, `ref.ts`) and the overlay are in every web bundle. The alternative is a separate entry that registers them (like a chart group), at the cost of a call that fails until it is imported; not done. Budgets in `scripts/size.mjs` were raised to the measured sizes.
21. **Protocol version pin.** The plugin depends on `@supersolutions/super-protocol` `0.3.0` exactly: the repo pins every dependency exactly (`check-package`), and for a 0.x version `^0.3.0` would allow only 0.3.x anyway. Say if a caret range is wanted for this one package.
