# Plot spec v1

> Generated by `scripts/export-spec.mjs` from the chart registry. Do not edit; run `npm run docs:spec`.

A plot is one JSON object: a `type`, the `data` rows, and the columns that map onto the chart. The same object is validated, rendered, described and turned into a JSON Schema, in every binding.

## Limits

| Limit | Value |
|---|---|
| `maxRows` | 50000 |
| `maxString` | 200 |
| `maxSeries` | 8 |
| `maxAnnotations` | 256 |
| `maxCategories` | 500 |
| `maxKey` | 128 |
| `maxNote` | 2048 |

## Transform steps

`transform` (every chart) is a list of at most 10 steps, run in order before the chart reads its columns; each step is an object with one key. Steps are plain data: there is no expression step, on purpose.

| Step | Keys | What it does | Example |
|---|---|---|---|
| `filter` | `field`, `equal`, `oneOf`, `range`, `gt`, `gte`, `lt`, `lte`, `valid` | Keep the rows whose `field` passes every test given: equal, oneOf, range [from inclusive, to exclusive], gt, gte, lt, lte (numbers or ISO dates), valid. | `{"filter":{"field":"region","oneOf":["APAC","EMEA"]}}` |
| `timeUnit` | `field`, `unit`, `as` | Bucket a date column to the start of its year, quarter, month, week (Monday), day or hour (UTC), as an ISO date in `as` (default: in place). | `{"timeUnit":{"field":"date","unit":"month","as":"month"}}` |
| `aggregate` | `groupBy`, `fields`, `count` | One row per group (`groupBy`, at most 4 columns) with `fields` reduced by sum, mean, median, min, max, count or distinct, and `count` rows. Only those columns remain. | `{"aggregate":{"groupBy":["month"],"fields":{"revenue":"sum"},"count":"orders"}}` |
| `sort` | `field`, `order` | Stable sort by `field`: numbers and dates by value, then text, missing last; `order` ascending (default) or descending. | `{"sort":{"field":"revenue","order":"descending"}}` |
| `top` | `n`, `by` | The `n` rows (1 to 1000) with the largest `by`. | `{"top":{"n":10,"by":"revenue"}}` |
| `bin` | `field`, `as`, `step`, `maxbins` | Round bins of a numeric `field`, as the histogram makes them: adds start and end columns (`as`, default [field_start, field_end]; a non-number gets null). `step` sets the width; otherwise the histogram step for `maxbins` (default 10), made coarser until there are at most `maxbins` bins. | `{"bin":{"field":"price","maxbins":10,"as":["from","to"]}}` |
| `window` | `op`, `field`, `as`, `groupBy`, `sortBy`, `order`, `frame` | Adds `as`: an op over each `groupBy` group walked in `sortBy` order (`order` asc or desc; no sortBy keeps the data order). sum, mean, count run cumulatively; rank is the standard competition rank of the sort key (1, 2, 2, 4; by `field` without sortBy); pctChange is (v - previous) / \|previous\|; lag and lead read the previous and next row; movingMean averages the last `frame` rows (default 3); ema is the exponential moving average with smoothing 2 / (`frame` + 1) (`frame` is its span, default 3: each row weighs 1 - 2 / (frame + 1) of the average before it). Rows keep their order. | `{"window":{"op":"sum","field":"revenue","as":"running","groupBy":["region"],"sortBy":"date"}}` |
| `fold` | `fields`, `as` | Wide to long: each row becomes one row per column in `fields`, with the column name in `as[0]` and its value in `as[1]` (default key, value); the folded columns are dropped. | `{"fold":{"fields":["Q1","Q2","Q3"],"as":["quarter","revenue"]}}` |
| `index` | `field`, `as`, `groupBy`, `sortBy`, `base`, `at` | Rescale `field` (into `as`, default in place) so each `groupBy` group equals `base` (default 100) at its base row: v * base / baseValue. The base row is the first in `sortBy` order (`at: "first"`, the default; no sortBy keeps the data order) or the row whose `sortBy` value is `at`. A group whose base value is 0, negative, missing or not found is dropped with an `index_group_dropped` warning that lists it. Compares growth of series of different size on one axis, instead of two axes. | `{"index":{"field":"revenue","groupBy":["region"],"sortBy":"month","base":100}}` |

## `bar` — Bar chart

Compares a number across categories with one bar per category (grouped, stacked or 100% stacked).

**Use when:** Comparing sizes across a handful to a few dozen categories, or parts of a whole per category (stacked). Use a line for ordered time; use a histogram to show how one measure is distributed; avoid for more than ~40 categories.

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `type` | string | yes |  | Chart type: bar. |
| `version` | `1` |  |  | Spec format version. Only 1 exists; may be omitted. |
| `data` | array of rows | yes |  | Tabular rows: an array of flat objects, one per observation. Numbers must be numbers (or plain numeric strings). |
| `title` | string |  |  | Chart title. State the takeaway or the subject, not "Chart". |
| `subtitle` | string |  |  | One line of context under the title: unit, period, filter. |
| `description` | string |  |  | Long description for screen readers and agents. Generated from the data when omitted. |
| `source` | string |  |  | Source line shown small under the chart. |
| `legend` | `auto` \| `top` \| `bottom` \| `right` \| `none` |  | `"auto"` | Legend placement. `auto` hides it for a single series and picks a side from the available width. |
| `tooltip` | boolean |  | `true` | Show a hover tooltip (web binding only). |
| `format` | format string |  |  | Value format: auto, compact, integer, percent (ratios, 0.25 shows as 25%), percent:N (exactly N decimals), fixed:N, currency:CODE. `currency:CODE:compact` abbreviates large amounts ($1.2B) and `:narrow` uses the narrow symbol ("$", not "US$"), in that order. A `~suffix` (1 to 16 characters) is printed after every value and axis tick, e.g. `integer~ days` shows 92 days; a `prefix^` (1 to 8 characters) goes before it, after the minus sign, e.g. `NT$^integer` shows NT$1,234. |
| `colors` | object |  |  | Series (or slice/category) name to CSS colour, e.g. {"Revenue":"#2962FF"}. Hex, rgb(), hsl(), a colour name or var(--x). Unlisted series keep palette colours. |
| `transform` | array of steps |  |  | Data steps run before the chart reads its columns, in order (at most 10): filter, timeUnit, aggregate, sort, top, bin (round bins: start and end columns), window (running sum, mean, count, rank, pctChange, lag, lead, movingMean, ema, per group, in a sort order), fold (wide columns to key/value rows) and index (rescale each group so its value at a base point is 100). No expressions. E.g. [{"timeUnit":{"field":"date","unit":"month","as":"month"}},{"aggregate":{"groupBy":["month"],"fields":{"revenue":"mean"}}}]. Column fields then refer to the output. |
| `patterns` | boolean |  |  | Default false. Add a texture per series to filled marks (bars, areas, slices, cells) so series stay apart without colour: colour-blind readers, greyscale print. |
| `key` | column name |  |  | Column that identifies each row (an id, read after `transform`). A reference names rows by it (`key=<id>`, see `resolveRef`); every row should have one, and each only once (`key_missing`, `key_duplicate` warnings). |
| `xLabel` | string |  |  | Title of the horizontal axis. |
| `yLabel` | string |  |  | Title of the vertical axis (include the unit). |
| `annotations` | array |  |  | Reference marks: {axis:"y", value:100, label:"Target"} draws a line; add `to` for a band. {xFrom:0, yFrom:0, label:"Expansion"} shades a region (xFrom, xTo, yFrom, yTo: numbers or dates on numeric or time axes; a side left out runs to the edge of the plot, so one corner makes a quadrant). {x:"2026-03-01", y:120, label:"Launch"} marks one point with a short leader and its label (x and y in the units of the horizontal and vertical axis: a category, a number or an ISO date). Either form takes `key` (a stable id, unique in the list, so a reference can point at it: `key=launch`), `note` (a longer explanation, at most 2,048 characters, shown as the mark's tooltip) and `by` (`author`, the default, or `assistant`: added by an assistant, drawn with a mark before the label and said so in the description). |
| `facet` | column name |  |  | Split into small multiples: one panel per value of this column (at most 12), sharing axes, colours and one legend. |
| `bare` | boolean |  | `false` | Default false. Draw only the marks: no axes, tick labels, grid, axis titles, title, subtitle, legend or source line, and almost no padding, so the plot fills its box. For a small trend inside a table cell or card (a sparkline). The title and description still name the chart for screen readers, and the tooltip still works. Fix the range with `yDomain` when the line should fill the height. |
| `zoom` | `none` \| `x` \| `xy` |  |  | Default none. Let the viewer zoom and pan a continuous axis (web binding): Ctrl/⌘-scroll or pinch to zoom, drag to pan, double-click or 0 to reset. Scatter, line and area. |
| `brush` | `none` \| `x` \| `xy` |  |  | Default none. Let the viewer drag out a range to select (web binding). The selection comes back as a filter step, ready for `transform`. With `zoom` too, Shift-drag pans. |
| `x` | column name | yes |  | Column holding the category of each bar. |
| `y` | column name or list of column names | yes |  | Numeric column for bar length. Several columns give one series per column (wide-form data). |
| `series` | column name |  |  | Column that splits each category into series (long-form data). Not needed when `y` lists several columns. |
| `stack` | `none` \| `stack` \| `normalize` |  | `"none"` | `none` groups series side by side, `stack` stacks them, `normalize` stacks to 100%. |
| `orientation` | `vertical` \| `horizontal` |  | `"vertical"` | Use `horizontal` for long category names or many categories. |
| `sort` | `none` \| `asc` \| `desc` |  | `"none"` | Order categories by their total. `none` keeps the data order (use it for ordered categories such as months). |
| `labels` | boolean |  | `false` | Print values on the bars. Keep off for dense charts; the tooltip carries the numbers. |
| `line` | column name or list of column names |  |  | Combo chart: numeric column(s) drawn as lines with points over vertical bars, on the same value axis (a target, an average). Ignored for horizontal and 100% stacked bars. For a measure in other units, see `yRight`. |
| `yRight` | column name or list of column names |  |  | Numeric column(s) drawn as lines with points over vertical bars (not horizontal or 100% stacked bars) against a second value axis on the right, with its own scale. Two scales on one plot can suggest a relationship (a crossing, a gap, parallel trends) that is only the choice of the two ranges: validation always adds a `dual_axis` info issue saying so. Prefer an `index` transform step on one axis, or two charts with `sync`. Each axis's title and tick labels take its series' colour (when it has one), the legend says "(right axis)", tooltips use `formatRight`, and the description says which series is on which axis. With a right axis, zoom and brush act on x only. |
| `yRightLabel` | string |  |  | Title of the right value axis (include the unit). Needs `yRight`. |
| `rightDomain` | [min\|null, max\|null] |  |  | Fix the right axis range, e.g. [0, 1]. Needs `yRight`. Without it the right axis is fitted to its series like the left one (on bars it always includes zero, and the two zeros line up). |
| `formatRight` | format string |  |  | Value format of the right axis, its tick labels and its series in tooltips (default: `format`). Needs `yRight`. |
| `yBreak` | [min\|null, max\|null] |  |  | Cut the span [from, to] out of the value axis (a broken axis), so one very large bar does not flatten the rest; bars that cross the cut are drawn shorter than their value. Grouped bars only (vertical or horizontal); the cut may not contain zero, where bars start (`break_misleading`). The cut is drawn as a zigzag gap across the axis and the plot, tick labels stay on both sides with the same units per pixel, and tooltips and the description give real values. Validation always adds an `axis_break` info issue with the hidden span; a value inside the span is a `break_hides_values` warning (drawn at the edge of the cut and marked). Refused on log and stacked axes and with `yRight`; zoom and brush on the broken axis are refused. |
| `yDomain` | [min\|null, max\|null] |  |  | Fix the value axis range, e.g. [0, 100]. Bars should start at 0; only change it knowingly. |
| `mark` | `bar` \| `lollipop` |  |  | Default bar. `lollipop` draws a thin stem from zero and a dot at the value instead of a filled bar: the same chart (sort, orientation, labels, grouped series side by side) with less ink, good for many categories. Not for stacks: falls back to bars with a warning. |
| `yLower` | column name |  |  | Numeric column with the lower end of an interval on y (a confidence or min-max range), drawn as a whisker with caps across each bar (grouped bars only; stacked bars ignore it with a warning). Needs `yUpper` too; the tooltip shows the interval and the axis includes it. |
| `yUpper` | column name |  |  | Numeric column with the upper end of the interval on y; see `yLower`. |
| `yScale` | `linear` \| `log` |  |  | Only `linear`. A bar's length starts at zero, which a log axis cannot show, so `log` is refused (`log_scale_refused`). Use a line or a scatter for values spanning several orders of magnitude. |

## `line` — Line chart

Shows how one or more numbers change along an ordered x axis, usually time.

**Use when:** Trends over time or any ordered numeric x, up to ~8 series. Use area for cumulative or part-to-whole over time, bar for comparing separate categories, scatter when both axes are measurements. For prices (OHLC, indicators, drawings) use Super Chart.

## `area` — Area chart

A line chart with the area under it filled; stacked areas show how parts add up over time.

**Use when:** Volume or cumulative quantity over time, and composition over time (`stack: "stack"` or `"normalize"`). Avoid overlapping unstacked areas for more than 2 series; use lines instead.

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `type` | string | yes |  | Chart type: area. |
| `version` | `1` |  |  | Spec format version. Only 1 exists; may be omitted. |
| `data` | array of rows | yes |  | Tabular rows: an array of flat objects, one per observation. Numbers must be numbers (or plain numeric strings). |
| `title` | string |  |  | Chart title. State the takeaway or the subject, not "Chart". |
| `subtitle` | string |  |  | One line of context under the title: unit, period, filter. |
| `description` | string |  |  | Long description for screen readers and agents. Generated from the data when omitted. |
| `source` | string |  |  | Source line shown small under the chart. |

| `tooltip` | boolean |  | `true` | Show a hover tooltip (web binding only). |

## `flow-map` — Flow map

Draws an arc from origin to destination per row, width by a number, on a globe or a flat map.

**Use when:** Showing movement between places: trade, migration, flights, shipments. Keep it to the biggest flows (a few hundred at most) or the map turns to string. Origins and destinations are lat/lng columns, or regions with a geography.
