## Decisions the owner may want to revisit

- `timeline` takes `y` for the lane; `task` was the brief's first suggestion. An alias would be a second name for one field, which the DSL avoids.
- Date-only values under a non-UTC `timeZone`: warn (`time_zone_dates`) instead of reading them as local midnights. Reading them as local would make parsing depend on a render option and disagree with `xDomain` normalisation and the ports.
- The stream graph hides value ticks entirely. A small scale bar ("this tall = 50") would restore magnitude reading without a fake zero; not built.
- Overlapping bars in one timeline lane are only warned about; packing them into sub-rows (as amCharts does) would be a later option.
- `strings` covers core only. The web binding has its own strings (keyboard help, data table captions, announcements) for the binding worker to add to the same map. React's option effect does not yet list `timeZone` / `strings` (they apply on mount only), and `<super-plot>` has no attribute for them: binding follow-ups, not changed here.
- Pre-existing, not changed: scatter's density-bin tooltip formats a time x range with the value formatter (numbers, not dates).

## Ports

New for the Go and Python ports: the `timeline` chart's fields (from `fields.v1.json`), its `check` (`timelineItems` in `charts/timeline.ts`: kind detection over start and end together, swap, skip, overlap per lane) and `describe` (uses `formatDuration` from `util/time.ts`; conformance has the example and two describe cases), the area `stack: "center"` enum value and its description sentence. `timeZone` and `strings` are render options and need nothing in the ports.
