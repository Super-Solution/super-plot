# Round 5, work package 8: navigator, drill-down, live announcements, print, touch

One spec field (`focus` on treemap and sunburst, through a new field kind `values`), one optional scene field
(`Mark.drill`), and web binding options/events. SPEC.md, the JSON Schema, `fields.v1.json` and conformance
(validation and description cases for `focus`) are regenerated; the Go and Python ports do not know `focus` or
the `values` kind yet.

| Feature | Borrowed from | How it fits the principles | Limits, refusals, decisions to revisit |
|---|---|---|---|
| `navigator` option: overview strip with a window and two handles | ECharts dataZoom slider, Highcharts navigator, Plotly rangeslider | One option on `SuperPlot`, no wrapper. The strip (`src/navigator.ts`, class `Navigator`) only reads scenes and writes through `AxisControl.viewX`, the same zoom state the wheel, keyboard, `setZoom` and sync use, so `onZoom` (once per gesture), `getZoom` and sync peers stay consistent. Drawn from the full-range scene (the scene on screen when unzoomed, else one extra compile without the view and without plugins, cached until data, size, theme, locale or hidden series change). Window and handles are `role="slider"` with `aria-valuemin/max/now` in axis units (epoch ms on time axes) and a readable `aria-valuetext`. | Line, area, scatter with `zoom` on a numeric or time x, no facets; otherwise `navigator_unsupported` (warning on every draw) and the chart keeps its height. Height: taken out of a fixed height, added below an automatic one (decision: a fixed-height host never overflows). Overview = first visible series (line/area) or a dot density strip (scatter, all visible series); long straight paths are thinned (first/min/max/last per column). Window min width = 1/500 of the range. `aria-valuetext` dates are UTC with `Intl.DateTimeFormat` (follow-up: read the new `timeZone` render option). The strip is SVG even when the chart is on canvas. Hydrated server markup is not adopted while the strip is on (different chart height). |
| `focus` spec field on treemap and sunburst; breadcrumb in the scene | ECharts treemap/sunburst drill, Highcharts drilldown + breadcrumbs, amCharts hierarchy | A field on the spec (agents can set it; validation, schema, describe, conformance follow from the DSL), not a binding-only state. New field kind `values` (a list of strings/numbers, normalised to strings). Breadcrumb drawn by core (`charts/drill.ts`) as text plus transparent `label` rects carrying `drill` paths: interactive SVG makes them buttons, canvas hit-tests them, static SVG keeps the text. Data marks of parents carry `drill` too. Colours stay those of the whole tree. | Unknown path `focus_not_found` (hint: did you mean + the names there), path ending on a leaf `focus_leaf`; both warnings, whole tree drawn. Treemap: only `[group]` (it has two levels); without `group` -> `focus_not_found`. While focused the legend is not drawn and legend toggles (`hidden`) are ignored (decision: the legend lists first-level branches, which a focused view shows one of). Sunburst "Share of total" stays relative to the whole tree. |
| Drill-down in the web binding: `drill` option, `onDrill`, `plot-drill` | same | The binding keeps a local focus path over the spec's (`specNow()`), never mutating the caller's spec; reset by `setSpec` only when the hierarchy or spec `focus` changes (new data keeps it). Click/Enter on a group drills (and still fires `onSelect`), breadcrumb buttons and Escape go up, keyboard focus moves to the first group (going up: to the group we left), the change is announced. React and the element pass `drill` and `onDrill` through (`drill`/`navigator` are also element attributes). | Default: on only with more than one level (sunburst `path` of 2+, treemap with `group`), per the brief's suggestion. With `drill: false` breadcrumb items are plain text (role and tabindex removed). Data arcs/tiles do not get an extra "press Enter to drill" description (revisit: `aria-description`). |
| Live-data announcements (`announce`) | Highcharts accessibility `announceNewData` | After `appendRows`, the existing polite live region (canvas: the layer's) says "N new points; latest <tooltip title>: <first two rows>", using the scene's own formatted tooltip of the mark at the newest row's x (`syncTarget`), so formats and locale match the chart. | Throttled to once per 5 s, counts summed. Default (decision): only while keyboard focus is in the chart or `dataTable` is on, so dashboards with many live charts stay quiet; `true` always, `false` never. Charts without axes say "N new rows." |
| Print | Highcharts / amCharts print | CSS: toolbar, tooltip, map buttons, navigator handles hidden; `break-inside: avoid`. Dark themes: CSS token swapping is not clean (sunburst, treemap, heatmap and others compute literal colours from theme values with `mix()`, and canvas pixels cannot be restyled), so the binding redraws on `beforeprint` with the light counterpart of a built-in dark theme (`dark` -> `light`, `accessible-dark` -> `accessible`, `auto` on a dark screen -> `light`) and back on `afterprint`. Option `printLight` (default true). | Custom dark Theme objects and page-level `--sp-*` overrides are left alone. Printers that do not fire `beforeprint` (some headless PDF paths) print the screen theme. |
| Touch: pinch and two-finger pan; 24 px targets | Plotly / ECharts touch, WCAG 2.5.8 target size | Verified with jsdom PointerEvent-shaped events (`pointerType: 'touch'`, two `pointerId`s). Pinch worked roughly but zoomed against the axes of the latest redraw (small drift) and had no two-finger pan. Fixed with a pure `pinchDomain(axis, domain, fromPx, toPx, factor)` against the axes as they were when the pinch began: zoom and pan together. Coarse pointers: a tap that misses picks the nearest mark with a tip within 12 px of its edge (`nearestMark`, SVG and canvas); CSS `(pointer: coarse)` grows hit circles to r 12, navigator handles, toolbar and map buttons. | No inertia. One finger after a pinch does not resume panning. `touch-action: pan-y` on x-only charts keeps vertical page scrolling; the browser may cancel a two-finger gesture that starts as a vertical scroll. |

Also fixed on the way: the canvas keyboard could not step through path marks without focus points
(sunburst arcs and other filled shapes): `markCenter` now falls back to the middle of the path's points
(`pathCenter`). `hostHeight()` ignores the navigator and a visible data table, which were counted as the
host's own height.
