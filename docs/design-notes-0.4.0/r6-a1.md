# Round 6, r6-a1: gauge and word cloud

For the lead to fold into DESIGN.md. Both were refused in round 5 (COMPETITIVE.md, chart types); the owner overruled
both refusals. Each is built safe by default, with the misleading risk stated in the docs and, where an agent can act
on it, as an issue with a code.

| Feature | Borrowed from | How it fits the principles | Limits and refusals | For the owner to revisit |
|---|---|---|---|---|
| `gauge` chart (`value`, `label`, `min`, `max`, `target`, `bands`, `bandOrder`, `arc`) | ECharts gauge, Highcharts solid gauge, AG Charts radial gauge, ApexCharts radialBar, amCharts gauge | A `ChartDef` in `charts/gauge.ts`; every field goes through the DSL (`bands` is `columns` with `min: 2, max: 3`, `bandOrder` and `rotate` enums, `arc` an integer), so validation, schema, SPEC, catalog and conformance follow. Data rows like every chart: one gauge per row, named by `label`. Thresholds are columns per row, as bullet's `ranges`, so no new field kind is needed and the ports validate it already. Exported `gaugeItems` and `gaugeScale` (the derived max rule) are what describe, check and compile share. Theme status tokens (`negative`, `warning`, `positive`) through `c.c(...)`; the value arc takes the value series colour, not the band's, so colour keeps one meaning. One transparent `path` over the whole track carries `tip`, `aria` and `datum` (so a gauge at its minimum, with no filled arc, is still hoverable and focusable; one keyboard stop per gauge); the filled arc carries `datum`; the target is a `line` in its own legend entry, as on bullet. | **Honesty**: the arc's *length* is the share of `min`..`max` and always starts at `min` (a 0 on -100..100 fills half); there is no needle-only mode. A value outside the range is clamped on the arc but printed as it is in the centre, tooltip, `aria` and description, with `value_outside_range` (and `target_outside_range`). Without `max` the top is `niceDomain(min, largest, 5)[1]` over values, targets and thresholds, with `max_derived` ("the share then says nothing about capacity"); nothing above `min` and no `max` is the error `max_required`; `max <= min` is `bad_range`. Bands: 2 or 3 (only three status tones exist), each named by its column in visible text beside the ring and in `aria`; the band of the value is printed under the number, so colour never carries it alone; unordered thresholds are sorted with `bands_not_increasing` (each band keeps its tone). Several rows need `label` (`missing_required`); at most 6 gauges (`too_many_gauges`, hint: bullet), repeated labels keep the first row (`duplicate_measures`). Grid: the column count that gives the largest radius; an incomplete last row is centred. `gauge_cramped` warns under a 40 px radius. **Facet refused** (not a field, so `unknown_field`): the rows already are the panels. Docs and `useWhen` point to a stat tile or a one-row `bullet`. | **No `info` severity exists** (`Issue.severity` is `error` \| `warning`), so `max_derived`, `value_outside_range` and the word-cloud notices are warnings. Adding `info` touches `Issue`, `validatePlot`'s `ok`, the error panel and both ports, so it was not done in a chart branch; convert them if `info` lands. **Shared range**: every gauge in a grid uses the same `min`/`max` (comparable at a glance); gauges in different units need separate charts. Per-row `min`/`max` columns could be added later. **Band thresholds per row** (columns) repeat in every row for the common "same thresholds" case, the same trade-off as bullet. Band segments have `aria` but no tooltip of their own (three extra tab stops per gauge otherwise); the gauge's tooltip lists every band's upper threshold. |
| `wordcloud` chart (`text`, `value`, `series`, `rotate`) | Highcharts wordcloud, visx Wordcloud (d3-cloud), echarts-wordcloud, amCharts WordCloud | A `ChartDef` in `charts/wordcloud.ts`. The layout is a pure exported function, `cloudLayout(words, width, height, measure)`, with its algorithm in the doc comment: an Archimedean spiral in 5-degree steps (72 per turn, 4 px per turn), stretched to the area's aspect, in **integer arithmetic only**: positions are `divRound(4 t cos5(k) W, 72 * 10000 * H)` with cosines from a 19-entry table (`CLOUD_COS`, cos of 0..90 degrees x 10000), boxes are whole pixels (`ceil(width) + 2` by `size + floor((size + 4) / 5) + 2`), and the first non-overlapping position inside the area wins. So the Go and Python ports reproduce it exactly given the same widths, without `sin`/`cos` (their fdlibm copies have neither). Conformance section `cloudLayout` carries the widths (core's `estimateWidth` at weight 500) with each case. Words are text marks (`role: 'data'`, `tip`, `aria`, `datum`, `series`) in value order, then a transparent `hit` rect per word (canvas hit index, and hover between glyphs). `cloudWords` (summing, ranking) and `cloudFontSize` are exported too. Colours: `series` groups through `makeSeries` (legend, toggles); without it a ramp from the theme's `text` to `seq-high`. | **Honesty**: font size `max(10, floor(maxFont * sqrt(value / largest)))` (area, not height, follows the value for equal-length words); what cannot be fixed is stated in the docs, `useWhen` and every description: *a long word looks bigger than a short one of the same value*. The description lists the top 10 words with their values in order; the data table lists every row; words under the 10 px floor are warned (`sizes_floored`); words that do not fit are left out and named (`words_dropped`) after up to three retries with fonts x0.8; more than 150 words keep the largest (`too_many_words`); values at or below zero are left out (`nonpositive_values`; none positive is the error `no_positive_values`); `patterns` is refused (`patterns_unsupported`: text has no fill). `rotate: 'none'` by default (all horizontal); `'some'` turns every fourth word in value order. Hiding a group keeps the other words in place (the layout runs on all words). **Facet refused**: the font scale is per panel, so panels would not compare. | **Server vs browser**: the server measures with the estimate, the browser with canvas, so the same spec can place words a few pixels differently (documented; the 1 px padding hides most of it). **Keyboard**: SVG tab order is value order; the canvas arrow keys go left to right as on every chart (the web binding orders by position; changing that is a binding decision, not made here). **Colour**: with `series`, the default palette's orange and yellow are under 3:1 on white, so small words in those groups are hard to read; the `accessible` theme or `colors` fix it, and the size and the tooltip carry the value anyway. The ramp's low end leans to the text colour (never to the background) so small words stay legible. A word in two groups takes its first row's group. `maxWords` was not made a field (a `top` transform step does it). |

## Conformance and ports

New data: validation cases for both charts (21), describe cases (6), and the `cloudLayout` section (5 cases, widths included). The Go and Python ports do not know either chart yet. To port: gauge's cross-field checks (`missing_required` on `label` with more than one row, `bad_range`, `max_required`, `max_derived`, `too_many_gauges`, `duplicate_measures`, `bands_not_increasing`, `value_outside_range`, `target_outside_range`, in that order, as in `check`), the derived max (`niceDomain`, already ported), both descriptions word for word, wordcloud's `no_positive_values`, `patterns_unsupported`, `nonpositive_values`, `too_many_words`, and `cloudLayout` with integer division (round half away from zero) and the cosine table. The layout's compile-time retry (fonts x0.8, at most four tries, keep the try that places most words, the first on ties) is in `compile`, not in validation or description, so the ports need it only if they ever draw.
