# Round 6, worker a2: two value axes, broken axes and the index step

Three features that the earlier rounds refused outright (`COMPETITIVE.md` had dual and broken axes at ⛔). They are
built here because every competitor offers them and agents will be asked for them; the safety measures below are what
lets them sit alongside the honest-baseline rule instead of breaking it. Everything is declared in the field DSL
(`yRight`, `yRightLabel`, `rightDomain`, `formatRight`, `yBreak`) or in `transform.ts` (`index`), so validation, the
JSON Schema, `docs/SPEC.md` and the conformance data follow. Shared logic is in the new `charts/valueaxes.ts`. Issue
severity gains `'info'` (`ctx.note`), used for `dual_axis` and `axis_break`: something a reader must be told about that
is not wrong.

## Deliberate refusals

- **A break on stacked or normalized bars, area, or log axes.** A stack crossing a gap would hide where one segment ends and the next begins. An area's fill is its message. A log axis already compresses the range, and breaking it as well leaves no readable scale.
- **A break that hides the bar baseline.** A bar's length is its value; cutting through zero makes it unreadable. The error suggests a span that every bar either crosses or stays below, or facets.
- **Zoom and brush across a break, or on y with two value axes.** The inverse of a broken scale is not continuous, and zooming one of two y scales leaves the reader with no stable reference. x keeps working, which covers nearly every real use.
- **Two value axes with a break at the same time.** Each is risky on its own. Together, the reader cannot tell which axis the gap belongs to.

## Decisions the owner may want to revisit

1. **Lines are not zero-aligned.** Bars align both zeros (they must, for honest lengths). Lines keep their own nice domains, because forcing zero into a line's range would flatten it. `rightDomain` is the lever when an author wants alignment.
2. **`alignZero` only extends domains, including a fixed `domain` or `rightDomain`, when it has to include zero on bars.** The alternative is to refuse the fixed domain. I extended it, because the bar baseline rule wins.
3. **On lines, the break is drawn as a gap over the lines.** Segments that cross the break are not split into two paths. The zigzag covers the jump. That is what Highcharts does, and it keeps the mark count stable, but a purist may want the path itself broken.
4. **Axis ink is a resolved hex value.** When the series colour fails the 4.5 contrast check, it is mixed toward the theme text colour. A theme that relies on CSS variables at runtime does not re-theme that ink without a re-render. The ink is recorded in `AxisInfo.ink`, so a binding could restyle it.
5. **SVG pointer events.** The gap polygon covers part of the plot, so the web binding adds `.sp-m.sp-annotation{pointer-events:none}` in `styles.ts`, and hover passes through all annotation marks. Canvas hit-tests only marks with tips, so it needed no change. Other bindings should do the same.
6. **The adapter does not convert right-axis cards** (Chart.js `yAxisID`, ECharts `yAxisIndex`) into `yRight`. It still warns, and its note now suggests `index` or `yRight`. Converting them silently would skip the author's decision to accept the risk.
7. **Visual baselines.** Three new gallery entries (`transform-index`, `line-dual-axis`, `bar-broken-axis`) need baselines from the owner's visual run. I did not run `test:e2e`, as the brief says.
8. **Ports.** Go and Python get the new fields through `fields.v1.json`. `yBreak` and `rightDomain` are of kind `domain`, so generic validation covers them. Still to do in the ports: the `info` severity, the `dual_axis` / `yBreak` cross-field checks and description sentences, and the `index` step. The conformance cases (`yRight: …`, `yBreak: …`, `index: …`) will fail there until then.
