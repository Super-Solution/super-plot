# Round 5, work package 3: spec fields and transforms

Everything below is a field on the spec or a transform step, declared once in the field DSL (or in `transform.ts`
for steps), so validation, the JSON Schema, `docs/SPEC.md`, the catalog and the conformance data follow. No new
chart type, no wrapper, no new dependency, no new mark type (the scene and both renderers are unchanged).

| Feature | Borrowed from | How it fits | Limits and refusals |
|---|---|---|---|
| `yScale: 'linear' \| 'log'` (line, scatter), `xScale` (scatter, line with numeric x) | Chart.js, Plotly, Vega-Lite, Highcharts, ECharts | Enum fields. `logScale` in `scale.ts` is a `LinearScale` with `log: true`, so every consumer of a continuous scale keeps working; `AxisInfo.scale: 'log'` tells bindings to invert, zoom and pan in log space (`interact.ts`: `invert`, `pixelOf`, `zoomDomain(d, at, f, axis)`, `panDomain`, the reset test). Ticks: `logTicks` (powers of ten, plus 2 and 5 when the range spans at most `count / 3` decades), labels in the value format (`compact` past 10,000 under `auto`). Domain widened to powers of ten (`niceLogDomain`). | Non-positive values are dropped with `log_nonpositive` (warning with the count; error when every value is non-positive). `log_bad_domain` for a domain at or below 0. Bar, area and histogram declare `yScale` only to refuse `log` with `log_scale_refused` and a hint (the honest-baseline rule: their marks start at zero). Log x on dates is refused the same way. `gaps: 'zero'` on a log axis breaks instead (`gaps_zero_log`). |
| `yLower` / `yUpper` (line, area, scatter, bar), `xLower` / `xUpper` (scatter) | Plotly `error_y`, Vega-Lite errorbar/errorband, Highcharts errorbar, ECharts custom | Column fields (`intervalFields` in `charts/extras.ts`). Line/area: one shaded band per series behind the lines (long-form `series` works). Scatter: error bars with caps. Bar: whiskers on grouped bars. Domains include the interval; tooltips, `aria` and `datum` carry both ends. The band and whisker marks are `role: 'data'` with the series (legend toggling and hover dimming work) and no tip, like a line's path: the hit strip or the dot carries the tip, so there are no extra tab stops. | Both ends required (`interval_incomplete`). Several `y` columns: no band, `interval_needs_one_y` (hint: fold to long form). Stacked area or stacked bars: `interval_ignored_stacked`. Swapped ends: `interval_reversed` warning, drawn between the two. Duplicate (x, series) rows sum their bounds, like their values. On a log axis an end at or below zero runs the bar to the plot edge without a cap. |
| Point annotations `{x, y, label, tone?}` | Highcharts annotations, Observable Plot text/tip, Vega-Lite text | A second form of the existing `annotations` items (no `axis` key). Ring marker, 16 px leader, label that flips left near the right edge and down near the top, clamped inside the plot. Listed in the description ("Marked: ..."), in `describePlot` and the scene. | `missing_required` for x, y or label, `bad_type`, `unknown_field` (a point with `to`, a line with `x`), `annotation_out_of_range` warning when the value is not on the axis. `x`/`y` are the horizontal/vertical axis (on a horizontal bar chart `x` is the value), as `axis: 'x'` already meant. Line and band forms validate exactly as before (conformance unchanged). |
| `gaps: 'break' \| 'connect' \| 'zero'` (line, area) | Chart.js `spanGaps`, Plotly `connectgaps` | Enum field without a default, so normalised specs (and old scenes, tested) are unchanged; `break` is what null or missing y did before. | Stacked areas always count a missing value as 0, as before. `zero` labels the tooltip "0 (missing)". |
| `trend: 'loess'`, `trendBandwidth` (0.05 to 1, default 0.3) | Vega-Lite loess, Plotly trendline | `loess(xs, ys, bandwidth, grid)` in `util/loess.ts`, pure and exported, with the exact algorithm in its doc comment (stable sort, q = clamp(floor(bw n), 2, n), sliding nearest window with a left tie rule, tricube weights, centred weighted least squares, 50-point grid). Conformance: `loess` cases. Linear and loess fits run in the axes' space (log10 on log axes). | No robustness iterations (Vega's default has two): simpler to port bit for bit; noted for the owner. `trend_bandwidth_ignored` without loess. Fewer than 3 points: no curve. |
| Bar `mark: 'bar' \| 'lollipop'` | Datawrapper, Flourish, Highcharts lollipop | Enum field on bar; the same compile path (sort, orientation, labels, groups, whiskers), a 2 px stem plus a dot that carries tip, aria and datum. Description says "Lollipop chart". | Refused on stacks with `lollipop_stacked` (falls back to bars). Patterns (`patterns: true`) do not texture lollipop dots (only rects and paths get textures); the legend still carries identity. |
| Transform `bin` | Vega-Lite bin, Observable Plot bin | Step `{ bin: { field, as?, step?, maxbins? } }`. Reuses the histogram's `binEdges` (moved to `util/bins.ts`, re-exported from `charts/histogram.ts`), so with the same target the edges match the histogram. | `maxbins` is a true maximum: when the histogram's round step gives more bins, the step is made coarser (1, 2, 5 times a power of ten). At most 200 bins (`too_many_bins` for a tiny `step`). Non-numbers get null bins with `some_not_numeric`. |
| Transform `window` | Vega-Lite window, Observable Plot window | Step with `op` sum, mean, count, rank, pctChange, lag, lead, movingMean; `groupBy` (≤ 4), `sortBy`, `order`, `frame`. The sort uses the existing sort step's rule. | Rank is the **standard competition rank** (1, 2, 2, 4), chosen because it matches spreadsheet RANK and Vega-Lite `rank`; dense rank is not offered. pctChange divides by the absolute previous value (a rise from -10 to -5 is +50%), null after 0. Output keeps the input row order. `frame_ignored`, `order_ignored` warnings. |
| Transform `fold` | Vega-Lite fold | Step `{ fold: { fields, as? } }`, wide to long; the folded columns are dropped (Vega-Lite keeps them) so the column set stays honest for later steps. | At most 50 fields; `too_many_rows` when the result passes 50,000 rows; `duplicate` for a field listed twice. |

## Deliberate refusals

- **No `calculate` (expression) step.** Evaluating text from a spec is an injection risk (agent output is untrusted input), and an expression language is a second language to port to Go and Python bit for bit. The window, bin, fold, timeUnit and aggregate steps cover the common derived columns; a host that needs more computes it before building the spec. A test checks that `calculate` is refused as an unknown step.
- **Log on bar, area, histogram** is refused, not silently drawn from an arbitrary floor.

## Decisions the owner may want to revisit

- The transform step limit stays at **10**. Three new steps do not make pipelines longer than about seven steps, and the ports already enforce 10, so raising it would change an existing conformance case for no gain.
- Log ticks thin to every second or third decade on long ranges; between 1/3 of the tick budget in decades and fewer, 2 and 5 are added. The thresholds are a judgement call.
- Long-form series with disjoint x values still break at each x another series has (existing behaviour of `break`); `gaps: 'connect'` joins them. Changing the default would change old charts, so it was left.
- An interval on a log axis below zero is drawn to the plot edge; an alternative is to refuse it.
- `yScale` exists on bar/area/histogram only to give a precise refusal; a reader of SPEC sees `log` listed and the description says it is refused.
- LOESS has no robustness iterations and a fixed 50-point grid (the function takes another grid size; the chart always uses 50).

## Ports

The Go and Python ports do not know these fields and steps yet (expected for this round). What they need: the new
fields come through `fields.v1.json`; cross-field checks to port are in `charts/extras.ts` and each chart's
`check`; the steps are in `transform.ts` (`bin`, `windowRows`, `fold`); numbers to match are in
`conformance/plot.v1.json` under `logTicks`, `logNiceDomain`, `loess`, `binStep`, and the new `validationCases`
and `transformCases`; descriptions gained short sentences for log axes, bands, error bars, loess, whiskers,
lollipops and point annotations.
