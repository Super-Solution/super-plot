# Round 6, worker c: animated transitions between data states

The owner overruled round 5's refusal ("motion between states hides what changed and costs every redraw") and
asked for transitions that are safe by default. Built as one web option, off unless asked for.

| Feature | Borrowed from | How it fits the principles | Limits and refusals | For the owner to revisit |
|---|---|---|---|---|
| `transition?: boolean \| { duration?: number; easing?: 'linear' \| 'cubic' }` (web option; React prop; `<super-plot transition>` attribute: present, a number of ms, or `"false"`) | ECharts, Chart.js, Highcharts, Recharts, Nivo, amCharts (all animate updates). uPlot, visx and Observable Plot refuse them, which is why it is opt-in and short | A render option, not a spec field: an agent's spec stays the same and SPEC.md, the JSON Schema and conformance do not change. No wrapper, no new dependency. Code in `packages/bindings/web/src/transition.ts`, loaded as its own chunk the first time a plot has the option (it is fetched by the constructor, so it is here long before the first update; `plot.ready()` waits for it). Cost to a page without it: 2.6 KB minified in `web base+bar+line` (the glue in `plot.ts`, `paintFrame`, the attribute), measured with `npm run size` | Default off. At most 1,000 ms (clamped), 300 ms by default, 0 turns it off. Never under `prefers-reduced-motion: reduce` or on a hidden page (both read when a draw starts and on every frame, so turning reduced motion on mid-flight jumps to the end), never on the first draw (the `animate` entrance covers it), never during a zoom, pan, brush or map drag, never when the chart type or renderer changes, never on WebGL (snaps: the GPU path redraws from `scene.geo`, a transition there would need its own shaders), never above 5,000 data marks, never for `appendRows` calls closer together than the duration (snaps to the end state) | The 5,000-mark limit is a guess at what a frame can afford on SVG (attribute writes) and canvas (a full `drawScene`); measure on slow devices. Drill-down (treemap, sunburst) redraws play the entrance, not a transition: it is a change of view, not of data; matching tiles by label would work if wanted |
| Matching by key | ECharts (`name`/data index), D3 key functions | Generic, in the binding, no change to core marks: the key is role, type, series and the datum's identity (its text and flag fields, a list of names such as a sunburst `path`, `x` when it is a number and there is no numeric `y`, a beeswarm `row`; timeline `start`/`end` are values, not names), then a running count so the n-th unnamed mark of a series matches the n-th. I considered adding a `key` field to scene marks in core: not needed, since every chart already puts its identity in `datum`, and leaving the scene alone keeps `renderToSvg` byte for byte the same and avoids touching 25 charts | Marks without identity (a line's path, its dots, scatter points, error bars) are matched in order. After `appendRows` those cross-fade instead of moving, because the n-th point is then another row (morphing a ring buffer's line would make every point wave to its neighbour's value) | A chart that wants better matching for unnamed marks (scatter points with an id column) would need a spec field naming the id column: not added, since nothing asked for it |
| What moves | Recharts, Chart.js | Rects interpolate x/y/w/h (and a numeric radius), circles cx/cy/r, lines their ends, data text its position, paths their numbers when the commands (and arc flags) are the same, else they cross-fade. New bars grow from the zero line (the edge of the bar nearest it; bottom or left without axes), other new marks fade in, gone marks fade out where they were. Colours follow the entity, so they are not tweened; base opacity is interpolated | Axes, ticks, labels (value labels included), legend, titles and hit targets snap to the final state: no invented tick numbers. Pie and sunburst arcs interpolate their end points linearly, so a slice is slightly off a circle in between (it ends exact) | Labels could fade in instead of snapping; left snapping as specified |
| Honesty | (our own) | `this.scene` is the final scene from the first frame, so tooltips, `aria`, the live region, the data table, `getScene()`, exports and `onRender` all describe the new data at once. On SVG the final DOM is mounted (aria, tabindex, `data-i` final) and only geometry attributes move; copies of gone marks sit in a `g.sp-ghost` with `aria-hidden` and no pointer events. On canvas the hit index, keyboard order and legend buttons are built from the final scene; frames only repaint pixels (`CanvasLayer.paintFrame`). A new update cancels the running transition and starts from the in-between geometry and fade | Plugins' `afterDraw` sees the final DOM/picture; on canvas it runs once more when the transition ends, since frames repaint the canvas (documented in INTEGRATION) | |
| Risk stated | | INTEGRATION.md "Transitions between data states" says what motion can hide (it draws the eye to what moved; in-between frames show values in no row) and when to use it; COMPETITIVE.md row moved from ⛔ to ✅ with the safety rules, and the "What was not copied" paragraph says why it was built | No `onIssues` info issue: the option is the host's, not the agent's spec, so an issue would reach no one who chose it | |

Core change: `roundedRectPath` is now exported from `@supersolutions/super-plot-core/base` (the SVG side of a
moving rounded bar needs the same path `renderSvg` writes). No scene type, chart or renderer output changed;
`renderToSvg` output is identical (conformance and SPEC checks unchanged).

Tests: `tests/web/transition.test.tsx` (20, jsdom with a fake `requestAnimationFrame` clock and `performance.now`):
option resolution and clamping, easing, datum identity and keys, matching (move, grow from zero, fade out),
path shapes and cross-fades, the append rule, hand-over of an interrupted plan, the SVG transition frame by frame
ending byte-identical to a direct render, default off, reduced motion (also turned on mid-flight), hidden page,
cancellation starting from the in-between state, 1,000 ms clamp, legend toggles and `setOptions({ hidden })`,
theme changes not animating, gestures, another chart type, fast and slow `appendRows`, the 5,000-mark limit,
no plan for WebGL, canvas frames with the final scene kept for hit testing and `afterDraw` re-run, the final canvas
frame drawing the same as a direct draw, and React / `<super-plot>` pass-through. Real browser
(`tests/e2e/features.e2e.ts`, new section on the features page with an SVG and a canvas chart): bars pass through
in-between heights, end identical to a fresh chart of the same spec, and snap under emulated reduced motion.
