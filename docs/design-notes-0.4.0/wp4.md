# Round 5, work package 4: web and React bindings

Web binding (`packages/bindings/web`), React binding, and one pure function in core. No spec fields, no chart
files, no `schema.ts` changes: everything here is a binding option, a method, an event or CSS, so SPEC.md,
the JSON Schema and conformance are unchanged (checked with `--check`).

| Feature | Borrowed from | How it fits the principles | Limits, refusals |
|---|---|---|---|
| `sync` option: linked hover, zoom, brush | uPlot `cursor.sync`, ECharts `connect`, Highcharts synchronized charts; the page-level part of Vega-Lite declared selections (OPEN-DECISIONS item 7) | One option on the existing class (`string \| { key, hover, zoom, brush }`), no wrapper, no global: a module-level registry (`src/sync.ts`) that plots join and leave (`dispose`, `setOptions`). Values travel as data (epoch ms, numbers, categories), so differently sized charts line up. Pure helpers `syncConf`, `xValueOf`, `syncTarget` are tested directly. | Defaults: string = hover + zoom on, brush off (mirroring a brush is surprising when charts also filter each other via `onBrush`). Only the plot the viewer used fires `onHover`/`onZoom`/`onBrush`; peers are updated like `setZoom`/`setBrush` (silent), and code-driven `setZoom`/`setBrush` are not shared: that is the no-feedback-loop rule. Match rule: same x axis *kind*; field names are not compared (grouping is the declaration). Skipped quietly: other kind, value off screen, facets, maps, horizontal bars (category on y). Zoom/brush reach a peer only if its spec has `zoom`/`brush`. Revisit: whether peers should also fire their own `onZoom`. |
| `tooltipFormat(tip, e)` | Chart.js tooltip callbacks, ECharts `formatter`, Recharts `content` | A hook, not a template language. String -> `textContent` (XSS-safe, `white-space: pre-line`), Node -> appended, null -> default. Same for pointer, keyboard (SVG focus and canvas steps) and synced tooltips. | A throwing function falls back to the default and reports `tooltip_format_error` once. The canvas live-region announcement keeps the plain default text (a Node has no reliable plain reading). |
| `plotCsv(spec, { maxRows, separator })` in core; `toCsv()` on plot and element | Highcharts export-data, Plotly / ECharts toolbox data view | Pure, DOM-free, built on `plotTable` (same columns and rows after `transform`). Also exports `csvCell`. | No row cap by default (validation caps data at 50,000). CSV injection: cells starting with `= + - @ \t \r` get `'`, except plain numeric strings such as `-42`; number values are never prefixed. Hidden series stay in the CSV (it is the data, as in `plotTable`). |
| `toolbar` option | Plotly modebar, Highcharts exporting menu, ECharts toolbox | Opt-in (default false, no change for existing users). Real `<button>`s in a `role="toolbar"`, accessible names containing the visible text (WCAG 2.5.3), keyboard, focus-visible ring, theme colours inline like the map controls, hidden when printing. Built once per item list so focus survives redraws (a new `mount()` keeps tooltip, controls and toolbar in place; this also fixes focus loss on the map zoom buttons). | `true` = png, svg, csv, table, reset (reset only when the spec has zoom). `sound` only when listed: playing audio is not an export and should be a deliberate choice. Shown on hover, focus-within and `(hover: none)`; overlays the top right (Plotly style) instead of adding a row, so a fixed-height host does not overflow. Reset uses `aria-disabled` (not `disabled`) so focus is not dropped. File names from the title, path and control characters removed, max 80 chars, `chart` fallback. |
| `sonify(options)` -> `{ stop, playing, notes, done }` | Highcharts sonification | A method, plus the pure `sonifyNotes(scene, options)` (exported) that turns a scene into notes (time, duration, frequency, value, label), so it is unit-tested without audio. Web Audio: one sine oscillator per note, 10 ms attack, exponential release, one master gain (`volume`, default 0.25). | First visible series only, x order (y order for horizontal bars, drawing order without axes; pie slices are one series). Pitch from datum values when every mark has one, else from height on screen. 220-880 Hz, log spacing; 120 notes max (sampled), 1.5-10 s by default. No AudioContext -> idle controller + `sonify_unavailable` warning; nothing to play -> `sonify_empty`. Second call stops the first and restarts; `dispose()` stops. Start/end announced in a live region (the canvas view's own when on canvas, so there is one per chart). |
| SSR hydration: `renderToSvg(spec, { hydrate: true })` | React/Vue-style hydration as used by Highcharts SSR and ECharts SSR (`renderToSVGString` + client `init`) | Small core change: the hydrate option writes the binding's own markup and stamps `data-sp-key` (FNV hash of the markup, `svgKey` exported) and `data-sp-id`. The binding's first draw compares the hash of what it would draw with the key; equal -> it moves the server `<svg>` into its root (no flash, no layout shift, no entrance animation) and attaches interactions; different -> normal draw, server markup removed. Exact, cheap (one serialisation, no DOM diff), honest. | Requires the same size, theme (incl. OS dark mode under `auto`), locale, plugins and text measure. A hydrated plot keeps the server's text estimator for its life, so later redraws do not move labels (decided; revisit if canvas-measured label fitting matters more). Plain `renderToSvg` output is never adopted or removed. React `<SuperPlot>` still renders an empty div on the server; hydrating through React would need a prop that injects the server SVG, left open. `display:block` is added to the stamped SVG's style (outside the hash) to avoid an inline gap before the script runs. |
| Forced colours / high contrast (CSS) | Highcharts accessibility module, WCAG 1.4.11 | `@media (forced-colors: active)`: the chart keeps its own palette and background like an image (`forced-color-adjust: none` on SVG and canvas), focus rings and brush in `Highlight`, tooltip in `Canvas`/`CanvasText`, buttons in `ButtonFace`/`ButtonText`, pressed in `Highlight`. `prefers-contrast: more`: thicker rings and brush, fainter dimming, toolbar always visible. | Not verified in a real Windows high-contrast session (jsdom does not evaluate media queries; the test checks the rules exist). Decision to revisit: letting the system force mark colours would erase series identity, so marks are not forced; `patterns: true` is the high-contrast-safe identity carrier. |
| Vue, Svelte, Angular | (OPEN-DECISIONS item 6) | No new packages: INTEGRATION.md has a correct example per framework (Vue `.prop` + `isCustomElement`, Svelte 5 property + `onplot-select`, Angular `CUSTOM_ELEMENTS_SCHEMA` + `[spec]`). The element gained an `options` property (any `SuperPlotOptions`, callbacks too; events still dispatched) and takes over properties set before `customElements.define` (upgrade), which is what frameworks do when the bundle registers late. | Svelte 5's `onplot-select` attribute form follows its "on + event name" rule; `addEventListener` is the fallback named in the doc. Not run against real Vue/Svelte/Angular builds (only the jsdom element contract is tested). |
| React | - | Passes `sync`, `toolbar` (compared by JSON value, so inline objects do not redraw) and `tooltipFormat` (stable wrapper calling the latest function). The ref is the instance, so `toCsv`/`sonify` come for free. | - |
| Element | - | New attributes `toolbar` (flag, comma list or `"false"`) and `sync` (key); new methods `toCsv`, `sonify`. A removed attribute falls back to the `options` property. | - |
